# 站点分页、清单预算与数据库超时

2026-10-29；只使用本地合成数据，不接真实站点或付费provider。

## schema v6与站点接口迁移

新增site_positions：持久AUTOINCREMENT序号、唯一site_id和外键级联删除。v5及更早数据库启动时自动迁移，旧站点按原rowid顺序回填。站点与序号在同一事务创建。备份工具接受v6并检查新表；v5备份恢复后可正常升级。升级前备份；不要让旧版程序继续写入已经升级的库。

`GET /api/v1/sites?limit=100` **由数组改为对象**：

```json
{"items":[],"next_cursor":null,"limit":100,"site_high_watermark":0,"order":"registration_sequence"}
```

默认100/最多500条，按注册序号排序。首屏固定上限，后续携带URL编码cursor；新增站点不会混入原遍历，已删除站点会跳过，删除最后一项也不会复用序号。没有新增HTTP删除站点接口；删除边界测试只操作无关联数据的临时站点。游标一小时有效、绑定管理员密钥和站点列表资源，不可与事件/审计游标互换。非法、重复、空查询参数返回400。每页限制payload读取字节（包括判断下一页的额外一条）及GET响应字节。

POST创建格式不变。演示脚本已逐页查找demo.example；测试把演示站点放在第101位，连续执行两次得到相同报告且不重复建站/增数。内部Service.sites仍返回完整列表，只供本地兼容调用。

## 清单导入和读取

导入保留最多10,000个URL的约束，在持久化前校验URL数组编码后的query_bytes预算及完整返回对象的response_bytes预算。超限422，不新增清单。新清单存储UTF-8 JSON，不用ASCII转义放大中文字符。

读取最新或指定清单时，在同一读事务先查ID和length(CAST(urls AS BLOB))；超预算则在读取URL正文与JSON解析前拒绝。旧快照按原始存储字节计量（包括历史ASCII转义），不会重写。报告复用同一入口，大清单也不能绕过预算；站点隔离和不可变快照保持。最终GET响应仍单独检查实际编码字节。预算限制请求量，不是整个进程内存承诺。

## 忙锁、查询截止与重试

普通数据库连接新增配置，服务和一次性mock worker均读取：

| 环境变量 | 默认毫秒 | 范围 |
| --- | ---: | --- |
| GEO_DB_BUSY_TIMEOUT_MS | 2000 | 整数1–60000 |
| GEO_DB_QUERY_TIMEOUT_MS | 5000 | 整数1–60000 |

忙锁交给SQLite的等待机制；查询截止时间在连接建立时计算，SQLite每约1000个虚拟机指令检查一次。它覆盖连接期间SQL执行的累计墙钟时间，不是每条语句独立计时，也不是整个HTTP请求硬超时；Python处理、锁等待和短语句不一定在截止点立刻中断。状态摘要保持自身两秒检查预算；迁移不使用运行期progress handler，避免启动升级受短查询限额影响。

| 情况 | HTTP / code | 调用方处理 |
| --- | --- | --- |
| SQLITE_BUSY / SQLITE_LOCKED（含扩展码） | 503 / database_busy，retryable=true，Retry-After: 1 | 延迟重试，采集保持原source/event_id，任务保持request_key |
| SQLITE_INTERRUPT（查询截止） | 503 / query_timeout，retryable=false | 缩小窗口/查询范围或评估后调整时限；不要原样自动重试 |
| 其他数据库运行错误 | 500 / 通用internal error | 排查服务状态和日志，不公开SQL或路径 |

提交失败或查询中断都会先关闭progress handler，再回滚整个连接事务并关闭连接，避免回滚本身再次触发截止。测试覆盖写入后中断、忙锁未写入、释放锁后重试成功。HTTP写入响应丢失仍存在结果未知情形；没有幂等键的创建操作须先检查现状，不能把任意网络错误都视为未执行。

## 本地HTTP多连接基线

`python scripts/http_load.py --seed 600 --rounds 20` 启动临时回环服务和临时库；不使用GEO_DB、不访问外网。4个线程，每次请求新连接；2个写线程各20批、每批20条，2个读线程各20次报告和20次站点分页。最终断言1,400条回答，并重放一批验证duplicates=20。

Windows / Python 3.12.14，在全量回归结束后独立运行一次：120次计时HTTP操作，0错误，5.075秒。Python追踪分配峰值8,011,045字节；进程生命周期驻留峰值71,356,416字节（Windows PeakWorkingSetSize）。

| HTTP操作 | 次数 | 中位ms | P95 ms | 最大ms |
| --- | ---: | ---: | ---: | ---: |
| 写入20条 | 40 | 101.13 | 139.54 | 201.74 |
| 报告 | 40 | 173.72 | 379.28 | 386.92 |
| 站点分页 | 40 | 17.12 | 71.32 | 90.79 |

客户端与服务端同进程，数值含序列化、连接和tracemalloc开销；驻留峰值包含启动与种子数据，不是工作阶段内存增量。小规模、单次测量，不能推算公网吞吐或生产容量；也不能直接与上一轮服务层基线比较得出性能优化结论。
