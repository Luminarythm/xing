# 审计分页、删除预算与并发验收

2026-10-29，本地合成数据，schema仍为v5，未增加运行依赖。

## 复核历史接口变更

`GET /api/v1/sites/{id}/mention-reviews?limit=100` 从数组改为对象：

```json
{"items":[],"next_cursor":null,"limit":100,"brand_config_id":"legacy","review_high_watermark":0,"order":"review_sequence"}
```

每项保留原始审计字段，新增递增sequence。同一回答的多次复核全部保留，分页不合并历史。limit为1–500，默认100，与报告总条数预算独立；单页仍受读取字节/GET响应预算，读取预算包含用于判断下一页的额外一条。

首屏固定品牌配置和复核序号上限。后续请求带URL编码的next_cursor，保持原brand_config_id参数（原来省略则继续省略），允许调整limit。之后新增的复核和配置变化不会混入本次遍历。删除优先：已删除的复核不会在后续页重现；递增序号不会因删除末尾记录而复用。

游标1小时有效，绑定站点、配置参数、接口资源及管理员token；跨站、改配置、篡改、过期、密钥轮换、把事件游标用于审计接口均拒绝400。需要管理员凭证，采集密钥无权访问。`geo/cursors.py` 共享签名逻辑，原事件游标签名和scope格式保持不变。内部Brands.reviews方法仍是带容量限制的完整列表，HTTP调用已换用review_page。

## 保留预览与执行预算

沿用GEO_MAX_QUERY_EVENTS（默认10000），**合计事件数+关联任务数+关联复核数**，并非只计事件。GEO_MAX_QUERY_BYTES限制选择中各行标识的JSON UTF-8字节累计；不读取待删除回答正文。plan新增selected_entities和selection_bytes用于核对预算。预览和执行都逐条检查，超过返回422；执行前数据变化仍需重新预览，容量先耗尽时可能先返回422，而非集合变化的409。

计划持久化JSON及返回JSON不能超过query_bytes和response_bytes中较小值。预览在INSERT前检查；执行在DELETE和保留边界更新前检查完成态结果（含deleted_at/removed_jobs）。因此“预览能返回、完成结果超限”也只会拒绝，不会删完才报容量错误。读取旧计划前先查存储长度，防止旧版大计划绕过新预算。

任一检查失败，事务回滚：不保存残缺预览、不部分删除事件/复核/任务、不推进保留边界。调低配置可使既有计划无法执行，需要调整预算或重新预览；完成态重试仍返回已保存的结果，但过大的旧结果也会被拒绝读取。

超限可选择更早截止日期，分时间批次重新预览和明确执行；如果大量记录集中于同一时刻，需评估后提高预算。不会自动分批或自动删除。本轮限制的是读取集合与序列化量，不是整个进程内存或SQL扫描耗时；BEGIN IMMEDIATE仍会在预览/执行期间串行化写入。

## 运行中缺库修复

过去sqlite3默认连接会在配置文件消失时创建空库，普通查询随后报“缺表”，留下误导性的空文件。现在初始化时固定绝对路径，只有显式Database初始化可创建新库；运行中连接使用mode=rw，缺失即失败，不创建替代文件。管理员状态仍使用只读连接返回503，普通数据接口返回通用内部错误。重新启动时仍可在配置路径创建新库，因此重启前必须确认路径和备份；本轮没有自动恢复功能。

## 固定规模本地并发基线

运行 `python scripts/local_load.py --seed 600 --rounds 20`。脚本仅在临时目录建库，结束即清理，不使用GEO_DB、不联网。4个线程：2个写线程各20轮、每轮20条；2个读线程各20轮报告与50条复核分页。初始化600条回答和120条复核，最后断言1400条回答；异常直接失败。

本机Windows / Python 3.12.14一次测量（含tracemalloc开销）：40次批量写、40次报告、40次审计分页，0错误，总耗时5.700秒；Python追踪分配峰值8,635,759字节。

| 操作 | 中位耗时ms | P95耗时ms | 最大耗时ms |
| --- | ---: | ---: | ---: |
| 写入20条 | 73.14 | 120.38 | 139.49 |
| 报告 | 241.44 | 333.73 | 352.69 |
| 审计50条分页 | 38.52 | 100.15 | 111.92 |

这是服务层、单机、小数据量基线；不是HTTP吞吐、不是进程RSS，也不涵盖SQLite原生内存或性能承诺。没有据此宣称生产容量或盲目增加索引。更大规模、真实日志形态、长审计历史与HTTP多连接仍待验收。
